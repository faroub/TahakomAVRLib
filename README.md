## Introduction

**TahakomAVRLib** is a C++ library to program Atmel AVR microcontrollers. 
The library makes use of the AVR standard C library and is written for easy usage.

Currently, the library supports popular DIY AVR microcontrollers including **ATmega328P** (Arduino Uno/Nano), **ATmega2560** (Arduino Mega), **ATmega168P**, **ATmega88P**, **ATmega48P**, and **ATtiny85**.

### Supported MCUs

| MCU      | Status     | Tested |
|----------|------------|--------|
| ATmega48P  | **Supported** | **Yes** |
| ATmega88P  | **Supported** | **Yes** |
| ATmega168P | **Supported** | **Yes** |
| ATmega328P | **Supported** | **Yes** |
| ATmega2560 | **Supported** | **Yes** |
| ATtiny85   | **Supported** | **Yes** |

The library includes an integrated local web server, web IDE, real-time telemetry oscilloscope, and 1-click flasher.


## Library structure 

The library is composed of several classes that abstract the internal elements of a microcontroller and some external components that when hooked up to the chip can perform some actions. 

These classes implement all functionalities and are organized into the namespaces: 

* core
* io (input/output)
* and components

Several [Applications](#applications) and [Projects](#projects) are implemented in order to demonstrate the library usage. 

A more detailed description of the code listings can be found in the [library documentation](TahakomAVRLibDoc.pdf) (generated by Doxygen)



## Software setup  

 Before using the library and start programming and interfacing external peripherals, some software packages need to be installed in your system: 

* binutils-avr: for getting tools like assembler, linker, ...
* gcc-avr : AVR GNU C cross-compiler
* avr-libc: AVR C library
* avrdude : driver program for downloading/uploading code and data from/to Atmel AVR microcontrollers



### Linux

In Linux (Ubuntu in my case), the software packages can be installed as follows:

```
sudo apt-get update
sudo apt-get install gcc build-essential
sudo apt-get install gcc-avr binutils-avr avr-libc
sudo apt-get install avrdude
```

### Windows

In Windows, the software packages can be downloaded and installed as follows:

* AVR toolchain for Windows: can be downloaded from the Microchip website (formerly Atmel) [GCC compilers for AVR and ARM](https://www.microchip.com/en-us/development-tools-tools-and-software/gcc-compilers-avr-and-arm)
* avrdude: can be downloaded from [GNU Savanna - avrdude](http://download.savannah.gnu.org/releases/avrdude/)
* make: can be downloaded from [make-3.81.exe](http://fab.cba.mit.edu/classes/863.16/doc/projects/ftsmin/make-3.81.exe) (precompiled for Windows)
* cmake: binary distribution can be downloaded from [cmake downloads](https://cmake.org/download/)

An alternative would be to download the precompiled AVR-GCC toolchain from [Zakkemble's AVR-GCC builds](https://blog.zakkemble.net/avr-gcc-builds/) that also includes avrdude and make utilities but not cmake.

Before using these software tools, you need to update the **PATH** environment variable with the file paths to their executables and restart the system.

*Note: The Windows setup instructions depend on the specific versions of make and cmake used. Newer versions may have different installation procedures or command-line options.*

## Compile and Flash programs

To compile and flash a program code to the AVR chip via USB port, you need to:

* Install the USB driver for the programmer used
* Adapt the CMakeLists.txt parameters to your system configuration: 
    * **MCU**: AVR chip used 
    * **F_CPU**: AVR CPU frequency
    * **BAUD**: Baud rate for serial communication
    * **PROG_TYPE**: Programmer type
    * **AVRFLASH_PORT**: Flash port name
* Change compiler flags if necessary
 
 and execute the following steps (shown for the [Blink a Led](applications/BlinkLed) application): 

### Linux

#### Linux permissions

To flash via USB, your user account needs access to the serial device (e.g. `/dev/ttyUSB*` or `/dev/ttyACM*`). On most distributions, you can add your user to the `dialout` group (or `uinput`/`serial` on some systems) and then log out and back in (or reload udev rules):

```bash
sudo usermod -aG dialout $USER
# or on some systems:
# sudo usermod -aG uinput $USER
sudo systemctl restart udev   # or just log out and back in
ls /dev/ttyUSB* /dev/ttyACM*  # verify the programmer is visible
```

If you see the device node listed, you're ready to flash.

```
../BlinkLed$ mkdir build
../BlinkLed$ cd build
../BlinkLed/build$ cmake ..
../BlinkLed/build$ make flash
```
### Windows

```
../BlinkLed$ mkdir build
../BlinkLed$ cd build
../BlinkLed/build$ cmake .. -G "Unix Makefiles"
../BlinkLed/build$ make flash
```

## Interrupt service routines

The library declares the interrupt service routines of its peripherals as
static member functions (e.g. `core::TimerCounter0::overflowServiceRoutine`,
`core::WatchdogTimer::timeOutServiceRoutine`).  For the vectors the library
itself never uses - the timer 0/1/2 compare and overflow vectors, the Timer 1
input-capture vector, the INT0/INT1 and pin-change vectors, and the watchdog
vector - it provides a **weak default**: an empty handler that immediately
returns.  An application takes ownership of any of those interrupts by
defining the same symbol, which silently overrides the default:

```cpp
#include <avr/interrupt.h>

ISR(TIMER0_COMPA_vect)      // overrides core::TimerCounter0::outputCompareMatchAServiceRoutine
{
    // your handler
}
```

The vectors the library fills with working handlers (ADC conversion complete,
SPI transfer complete, and the three USART0 interrupts) cannot be overridden;
the library owns them.

Note for custom builds: the startup code of the C runtime weakly aliases
every unused vector to `__bad_interrupt`, and the first weak definition wins
the link.  Both the `scripts/check_build.sh` harness and the application
CMake files therefore link the CRT startup object *after* the libraries, so
the library weak defaults take effect.  Keep that order when building the
library into your own project.


## Local Development Server & Telemetry Web IDE

The project includes an integrated local development platform:

```bash
# Start the local development platform server
python3 server/app.py
```

Then open `http://localhost:8000` in your web browser to access:
* **Web C++ Editor**: Write sketches with auto-linking against TahakomAVRLib.
* **1-Click Build & Flash**: Automated `avr-g++` cross-compiler and `avrdude` flasher.
* **Real-Time Oscilloscope & Logic Analyzer**: Visual canvas plots streaming hardware telemetry frames (`io::Telemetry`).
* **Pre-Flash Host Simulator**: Run simulation binaries natively on host x86.
